The paper’s central contribution is the SAFE framework: a two-stage, self‑evolving pipeline that bootstraps from GPT‑4o and then iteratively fine‑tunes open‑source LLMs to (i) synthesize Verus specifications for Rust code and (ii) generate and repair full proofs, using verifier feedback and incorrect proofs as training signal. Closest prior work already covers substantial parts of this space but not this integration. Baldur (First et al., 2023) fine‑tunes LLMs for whole‑proof generation and trains a repair model from failed proofs and error messages, but works in Isabelle/HOL and does not implement a multi‑round self‑evolution loop or spec synthesis. For Rust/Verus specifically, Yao et al. (2023), Selene (Zhang et al., 2024), and AutoVerus (Yang et al., 2024) all use GPT‑4‑class models plus verifier feedback to generate/repair proofs or invariants, but remain prompt‑orchestration systems without automated dataset bootstrapping, quantitative spec filtering, or iterative fine‑tuning of an open model. The submission’s delta is therefore the concrete, end‑to‑end self‑training architecture for Rust/Verus—combining spec synthesis, proof synthesis, and self‑debugging in a multi‑round fine‑tuning loop—which is central rather than peripheral. Given that no prior work delivers this core mechanism, the overall novelty is a genuine advance.
