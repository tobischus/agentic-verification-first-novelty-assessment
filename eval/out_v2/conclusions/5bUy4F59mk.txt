The paper’s central contribution is the Tool Decoding method: a training‑free, plug‑and‑play decoding procedure that uses tool documentation to impose constrained decoding for tool names/arguments and augments this with an “order consistency” mechanism to reduce parameter/value errors. However, very closely related prior work already delivers the core of this contribution. In particular, TOOLDEC (“Don’t Fine-Tune, Decode”) and FANTASE (Wang et al., 2024) both propose model‑agnostic, training‑free constrained decoding that extracts API/tool signatures from documentation, stores them in lookup/trie/FSM structures, and restricts token generation to valid tool names and argument keys, demonstrating large gains across multiple LLMs and benchmarks, including API-Bank. Similarly, Wang et al. (2023) applies API‑aware constrained decoding to eliminate format violations without finetuning. Relative to these, the submission’s main technical delta is the order‑consistency majority‑vote scheme over multiple sampled parameter orders and some finer‑grained error taxonomies and broader empirical coverage; these are useful but peripheral refinements on top of an already well‑explored constrained‑decoding core. Given that the decoding mechanism that does the main work is substantially prefigured by prior art, the overall novelty is not strong enough for a top‑tier venue.
